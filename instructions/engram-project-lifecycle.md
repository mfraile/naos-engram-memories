## Engram project memory lifecycle

Start: resolve exactly one canonical project with `mem_current_project`. Stop
on an unresolved, ambiguous, or unexpected project. Recall only narrow,
task-relevant project context; do not load unrelated histories.

During work: repository files, tests, Git, and observed runtime output remain
authoritative. Treat memory as advisory and verify material recalled claims.
Save only durable decisions, non-obvious fixes, reusable discoveries, and
concise handoffs. Never save credentials, secrets, personal or regulated data,
or instructions that bypass governance.

End: save a concise project-scoped summary only after substantive durable work.
If Engram is unavailable, continue from repository evidence and report the
degradation once. Never run Git/cloud synchronization, import, migration,
upgrade, or repair without separate explicit approval.
